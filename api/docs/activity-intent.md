# 活动意向登记与官方活动

## 已实现链路
- 首页“我的活动意向”和同城空态可打开底部表单，登录后读取该城市已有登记。
- 地图选点保留经纬度和地址，从结构化逆地理编码结果取得城市，不再从完整地址猜城市；解析期间禁止提交，重新打开地图回到已选位置。
- 切换地图城市后查询该城已有登记，支持修改与取消；保存按用户和城市去重，类别在同一登记内多选。
- 官方账号由后台授权。官方发布默认置顶，接口在分页前排序，App 卡片展示置顶标识。
- 官方不作为到场成员，不设召集人；活动详情说明意向征集、不承诺举行。双方从个人主页私聊，不创建群或绑定活动会话。

## 接口契约
- GET /user/activity-intents?city=杭州市：当前用户该城有效登记，不传城市时按50条分页。
- PUT /user/activity-intents：新增或修改同城登记。
- DELETE /user/activity-intents/:id：取消当前用户的登记。
- GET /admin/activity-intents：后台按城市和页码查看有效登记。

保存请求：city（城市）、latitude/longitude（地图坐标）、locationText（选点地址）、categoryIds（数字ID数组）、timeSlots（约定的中文时段数组）、note（最多200字）、notifyEnabled（通知意愿）。坐标不可缺失，服务端校验有限数值与范围。回执 id 为字符串。

## 通知规则
审核通过后匹配发布前已经登记的有效用户：城市一致、类别一致、notifyEnabled=true、用户正常，排除运营本人。发送前重新检查活动和登记有效性。
时段和地图坐标仅记录偏好，不用于当前通知过滤。没有活动群，不自动报名。使用既有站内信与推送服务，尊重系统通知设置。
持久化任务按活动和用户去重，每15秒检查，失败最多尝试5次；失败原因保留在 intent_notifications。站内信使用唯一幂等键；外部推送超时存在至少一次投递的重复边界，客户端沿用消息ID去重。
